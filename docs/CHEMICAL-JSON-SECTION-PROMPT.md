# 化工产业链 SAG 分章节 JSON 抽取提示词（配合本地合并脚本）

这套提示词用于"**一次只喂一个章节/小节给网页版 AI**"的工作流：

1. 用本提示词逐节抽取，每节得到一个 `{ "chunks": [...] }` 的 JSON。
2. 把每节的 JSON 存成 `01-xxx.json`、`02-xxx.json`…… 放进同一个目录。
3. 用 `tools/import-prep/merge-and-validate.mjs` 合并成**单个文档**、连续重排切片编号、并按导入端规则校验。
4. 把合并产物上传到 SAG 网页"粘贴或上传网页版 AI 的数据"。

关键点：因为 SAG **每次导入都新建一个文档**，所以同一来源文档的所有章节必须先合并成一个文件、一次导入，才会落在同一个文档下。本提示词让 AI 只产出 `chunks`，文档标题和来源信息由 `meta.json` 统一提供，AI 不必每节重复（也就不会每节乱猜来源）。

把下面整段复制给网页版 AI，然后**只粘贴当前这一个章节/小节**的原文。

```text
你是一名化工产业链和期货知识抽取专家。我会分多次把同一篇资料的不同章节发给你，每次只发一节。请只针对我这次发给你的这一节内容做抽取。

只输出合法 JSON，不要输出解释、总结、Markdown 代码块或 JSON 以外的任何文字。

## 输出结构（重要：只输出 chunks，不要 documents、不要 source、不要 title）

{
  "chunks": [
    {
      "key": "1",
      "heading": "",
      "content": "",
      "event": {
        "title": "",
        "summary": "",
        "content": "",
        "category": "",
        "keywords": [],
        "entities": [
          { "type": "", "name": "", "description": "", "relation": "" }
        ]
      }
    }
  ]
}

- key 在本节内从 1 开始递增即可，不用管和别节是否重复（合并脚本会全局重排）。
- 不要输出 title、source、documents、id、documentId、chunkId、eventId、schemaVersion、metadata、embedding、时间戳等任何字段。

## 任务本质

这不是摘要，也不是 QA，而是抽取"原文证据切片 + 一个最小完整产业链事件 + 该事件的关键实体"。SAG 以事件为中心，事件像知识超图里的一条超边，连接多个实体。一个事件表达一个最小完整产业链事实，而不是零散三元组。

- content：可核验的原文证据，回答"原文怎么说"。尽量贴近原文（含必要的限定、单位、口径），不得加入原文没有的信息。
- event.content：在 content 基础上去冗余、补全主语和关系后的完整事实陈述，回答"这段表达了什么事实关系"。推荐结构【时间/口径】+【主体】+【关系/动作】+【对象】+【数值/变化】+【原因/条件】。
- content 与 event.content 一般不应完全相同，除非原文本身极短且无冗余。
- 一个 chunk 原则上对应一个 event；一个 event 通常含 3～8 个高价值实体，身份类短事件可少于 3 个。

## 拆分 / 合并规则

必须拆成多个事件：关系类型不同、时间范围不同、指标口径不同、变化方向不同、因果不同；每个对象有独立数值/趋势/原因；上游原料、直接下游产品、终端应用领域混在一起；品质分级不同且对应不同市场。
应合并为一个事件：同一化工品的名称/别名/简称/英文名/CAS号/化学式；同一产品的多个并列下游或应用（仅并列列举时）；同一工艺/装置的多个并列产物；同一企业同一时间同一事项的多个并列装置/产品/基地。

## 必须区分的维度

- 直接下游产品（继续反应/加工出的具体产品，如双酚A→聚碳酸酯）≠ 终端应用领域（最终进入的行业，如电子电器、汽车、光伏）。
- 品质分级（电子级/食品级/医药级…）、准入合规（GMP/安全生产许可证/ISO9001/农药登记证…）、功能角色（核心原料/催化剂/溶剂…）、来源属性（联产/副产/回收/进口依赖）四者不可互相替代，原文同时出现就分别提取。
- 带等级产品名（如"电子级氢氟酸"）：产品实体写基础名（氢氟酸），品质分级实体写"电子级"，event.content 保留完整表达。

## 表格与行情

表格必须把表头、行名、列名、单位、时间口径并入 content 和 event.content，不能只抽单元格数值。价格/利润/库存/开工率/价差/加工费等行情必须作为事件，event.content 含：产品+指标+时间/周期+数值/方向+单位+口径+原因/结论。这些数值、时间、指标名、变化方向不要作为实体。

## 实体规则

- 每个实体只表示一个对象，不要把多个实体塞进一个 name。
- type 优先用：原料、中间体、产品、下游产品、联产品、副产品、生产工艺、化学反应、催化剂、生产设备、企业、供应商、采购商、生产基地、项目、装置、化工园区、行政地区、市场区域、港口、仓储、能源、政策、法规、标准、监管机构、行业组织、CAS号、化学式、危险性、应用领域、终端行业、别名、简称、英文名、品质分级、准入合规、功能角色、来源属性、牌号/规格。
- description 写实体本身是什么；relation 写它在本事件中的角色（如"双酚A的直接下游产品之一""该产品的来源属性，为副产"）。
- 不要把时间、日期、数值、单位、产能、价格、库存、开工率、变化方向、动作词、程度词、泛称角色抽成实体；它们留在 event.content。
- keywords 是字符串数组，含标准名、别名、简称、英文名、CAS号、核心产业链词、重要口径词。

## 不要抽取

没有明确产业链事实的背景句、过渡句、标题句、风险提示、免责声明、泛泛判断。只有出现明确的产品/企业/工艺/上下游/应用/指标/合规/来源属性/时间口径/数值时才生成 chunk。

## 输出前自检

- 顶层只有 chunks 数组；没有 title/source/任何 id。
- 每个 chunk 有 content、heading、event；event 有 title、summary、content、category、keywords(数组)、entities(数组)。
- 每个 event 至少 1 个含 name 的实体。
- content 是原文证据，event.content 是去冗余后的完整事实，二者一般不同。
- 没有把多个实体合并进一个 name；没有把数值/时间/指标抽成实体。

现在开始：只处理我接下来这一条消息里的章节原文，只输出 JSON。
```

## 配套的 meta.json

在章节目录里放一个 `meta.json`，整篇资料只填一次：

```json
{
  "title": "（这篇资料的文档标题，决定导入后文档名）",
  "source": {
    "name": "报告名 / 网页标题 / 公众号文章名",
    "type": "report",
    "date": "2025-03",
    "author": "作者或机构",
    "url": ""
  }
}
```

`type` 可选：`report`、`web_article`、`markdown`、`book`、`manual`、`database`、`unknown`。判断不了就 `unknown`，其余留空字符串。
