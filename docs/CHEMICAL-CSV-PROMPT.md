# 化工产业链 CSV 抽取提示词

把下面整段提示词复制给网页版 AI，然后上传需要处理的化工文档。

```text
你是一名化工产业链和期货知识抽取资深专家。请阅读我上传的文档，把内容整理成可以导入 SAG 知识图谱的标准 CSV。

## 核心目标：

本任务不是摘要，而是面向化工产业链知识图谱的细粒度事件抽取。SAG 中的“事件”会作为知识图谱里的超边，因此事件应表达一个完整的产业链事实关系；同一事件中允许并且应该提取多个实体。SAG 是一种以事件为中心、用 SQL 动态串起线索的 RAG 架构。它不预先构建庞大的知识图谱，而是把原始文本整理成“事件+ 实体”的数据库结构。查询时，再围绕当前问题，用 SQL 动态连接出局部线索网。SAG 用 LLM 将每个文本块切片处理成一个事件，而不是拆成很多零散的三元组。一个事件描述一件完整的事，并连接多个实体。在数据结构上，就像一个知识超图的“超边”，把多个实体绑在一起。

## 抽取原则：

1. 按"一个最小完整关系单元一个切片"的原则拆分文档。一个切片只对应一个事件。
2. "最小完整关系单元"指同一主体、同一关系类型、同一时间或统计范围、同一事实语义下的一组事实。
3. 不要把不同关系类型、不同时间范围、不同指标口径、不同变化方向、不同因果逻辑的事实合并成一个事件。
4. 也不要把同一关系事实下的并列实体机械拆成多个事件。一个事件中可以有多个实体，并通过多行 CSV 表达。
5. 只提取文档明确表达的事实，不补充、推测或改写文档中没有的信息。
6. 如果原文出现"疑似""可能""相关"等不确定表达，必须在事件内容和实体说明中保留不确定性。
7. 每个切片建议保留 80～700 个中文字符；短事实如简称、别名、CAS号、价格、产能等可少于 80 字，但必须保留可核验原文。
8. 允许多个切片复用同一段原文，只要对应的事件不同。
9. 必须尽可能保留文档中的细节，包括但不限于大宗或精细化工品的名称、别名、简称、cas号、化学式、原料、生产工艺、中间体、企业（采购商和供应商等）、直接下游产品、终端行业、供应需求库存等指标变化（必须包含日期和频率，比如截至x年x月x日当周的x数据……）和事实依据，如果文档中有原料的定额、工艺的收率、副产或联产等的比例、下游产品消费的比例、公司的产量或消费量等数据，也必须作为事件保存下来。
10. 文档中如出现品质分级（如食品级、电子级）、准入合规（如GMP认证、SC食品生产许可证）、功能角色（如核心原料、功能助剂）、来源属性（如联产、副产、回收再生）等信息，必须按下文"维度判断规则"一节分别归位提取，不能相互混淆、合并或遗漏。

## 应合并为一个事件的情况：

1. 同一化工品的名称、别名、简称、英文名、CAS号、化学式等身份信息。
2. 同一产品的多个并列终端应用领域。
3. 同一产品的多个并列下游产品，且原文只是并列列举。
4. 同一工艺或装置的多个并列产物，且原文只是并列列举。
5. 同一企业在同一时间范围内的同一事项，涉及多个并列装置、产品或基地。
6. 同一市场状态下的多个并列指标，且原文没有分别给出独立原因或结论。
7. 同一产品同一品质分级下，多个并列的准入合规要求（如同时列出生产资质和供应商资质），且原文未分别给出独立背景、依据或结论。

## 必须拆成多个事件的情况：

1. 关系类型不同，例如产品定义、生产工艺、应用领域、产能变化、价格变化、利润变化、供需变化等。
2. 时间范围不同，例如 2024 年和 2025 年。
3. 指标口径不同，例如价格、利润、库存、产能利用率、进口依赖度等。
4. 变化方向不同，例如上升、下降、持平、改善、恶化。
5. 每个对象有独立数值、趋势、原因或结论。
6. 上游原料、直接下游产品、终端应用领域应区分，不要混成一个事件。
7. 生产工艺变化方向不同，例如"乳液法产能占比下降"和"连续本体法产能占比上升"应拆成两个事件。
8. 品质分级不同，例如同一化工品的"食品级"和"工业级"对应不同市场、不同价格体系，应视为不同事实分别提取，不要合并。
9. 准入合规所属层级不同，例如"生产端准入"和"使用端准入"分别约束不同主体，应分别提取，不要合并不同层级的资质要求。
10. 功能角色与来源属性是两个独立维度，原文同时给出两者且分别有独立说明时（例如分别说明"作为核心原料的用法"和"作为副产物的来源"），按各自的事实主体拆分；若两者描述的是同一关系事实的不同侧面，则保留在同一事件内用不同实体行表达，不要互相替代或只提取其中一个。

## 本任务特别关注化工产业链数据集中的四个商业语境维度：

1. 品质分级：产品是什么级别。
2. 准入合规：进入某市场、生产、销售或使用该产品需要什么资质、许可、标准或认证。
3. 功能角色：上游产品在下游场景中发挥什么功能。
4. 来源属性：产品来自常规生产、联产、副产、回收再生、进口依赖等哪种供应来源。

完整商业语境 = 品质分级 + 准入合规 + 功能角色 + 来源属性。

## 重点抽取对象：

必须尽可能抽取以下信息作为事件或实体：

- 化工品名称、别名、简称、英文名、CAS号、化学式；
- 原料、中间体、产品、副产品、联产品；
- 生产工艺、化学反应、催化剂、生产设备；
- 企业、采购商、供应商、生产基地、装置；
- 产能、产量、消费量、库存、价格、利润、开工率、产能利用率、进口依赖度、行业集中度；
- 原料定额、工艺收率、副产比例、联产比例、消费比例；
- 直接下游产品、终端应用领域、终端行业；
- 品质分级（通用级、食品级、医药级、电子级、试剂级、化妆品级、饲料级、农药级、军工级、核级、航空级、光学级）；
- 准入合规（生产端准入、使用端准入、产品端认证、供应商端资质，例如安全生产许可证、GMP、SC食品生产许可证、农药登记证、ISO 9001等）；
- 功能角色（核心原料、结构共聚物、功能助剂、催化剂、溶剂/介质、工艺辅料、中间品）；
- 来源属性（常规生产、联产、副产、回收再生、进口依赖）；
- 时间、日期、周期、统计口径，例如"2025年""截至某日当周""月度""年度"。

## 维度判断规则（抽取前必须先判断信息属于哪个维度，再决定填入哪个实体类型）：

一、品质分级 vs 准入合规

一句话判断：原文描述的是"产品本身达到什么纯度/级别" → 品质分级；原文描述的是"要拿到什么资质才能生产/卖/用这个产品" → 准入合规，不是品质分级。

品质分级标准包括 12 大类：

通用级、食品级、医药级、电子级、试剂级、化妆品级、饲料级、农药级、军工级、核级、航空级、光学级。

常见同义表达为：

工业级、普通级、标准级、大宗级、基础级、常规级、技术级 → 通用级。
食用级、食品添加级、食品卫生级、食品接触级、食品用、FCC级 → 食品级。
药用级、药典级、CP级、USP级、EP级、注射级 → 医药级。
半导体级、超净级、超纯级、ppt级、ppb级、光伏级、面板级、晶圆级 → 电子级。
分析纯、优级纯、化学纯、光谱纯、色谱纯、基准试剂 → 试剂级。
日化级、化妆品原料级、IECIC收录级 → 化妆品级。
饲料添加级、饲用级 → 饲料级。
原药级、制剂级、农用级 → 农药级。
国军标级、军用级、军品级、GJB级 → 军工级。
核电级、核安全级、核用级、1E级 → 核级。
适航级、AMS级、航空材料级 → 航空级。
透光级、折射率级、光学材料级 → 光学级。

常见错误对照（必须避免）：

- "无需认证" → 不是品质分级，应记为准入合规：准入要求=无
- "GMP认证""药品生产许可证" → 准入合规-生产端准入，不是品质分级
- "饮用水卫生许可" → 准入合规-使用端准入，不是品质分级
- "医疗器械认证" → 准入合规-下游产品准入，不是品质分级
- "出口法检""出口资质" → 准入合规-贸易合规，不是品质分级
- "半导体级""电子级" → 是品质分级，不要误标为认证或功能角色

准入合规四层级（按约束对象和阶段分类）：

- 生产端准入：生产该产品需要的资质，例如安全生产许可证、排污许可证、药品生产许可证、GMP、农药生产许可证、食品生产许可证、武器装备科研生产许可证等。
- 使用端准入：下游客户使用该产品需要的资质，例如危化品使用许可证、食品生产许可证、医疗器械生产许可证、核安全设备制造许可证、饮用水卫生许可等。
- 产品端认证：产品本身需要通过的标准、认证、检测、备案或登记，例如食品添加剂国家标准审批、农药登记证、化妆品原料备案/注册、建筑材料认证、阻燃认证、出口法检等。
- 供应商端资质：供应商需要具备的资格，例如 ISO 9001、ISO 14001、IATF 16949、特种设备制造许可证、危化品经营许可证等。

准入合规可以作为事件抽取，但资质、许可、认证、法规、标准是否作为实体，要看其是否是具体名称。具体标准、法规、许可证、认证名称可以作为实体；“准入”“认证要求”“合规门槛”等泛称不能作为实体。

二、功能角色 vs 来源属性 vs 品质分级

三者经常被混在一起，必须拆开：功能角色回答"这个产品在下游生产中起什么作用、采购量级多大、谁来决策"；来源属性回答"这个产品是怎么生产出来的、供应稳不稳"；品质分级回答"这个产品是什么纯度级别"。三者互相独立，同一产品可以同时具备三个标签，缺一不可，不能因为提取了一个就省略另外两个。

功能角色标准（包括但不限于以下角色）：

- 核心原料：构成下游产品主体结构的原料（如甲醇→MTO、MDI→聚氨酯泡沫、VCM→PVC）
- 结构共聚物：与核心原料共同构成产品结构的共反应物（如苯乙烯→SBS、丙烯腈→ABS）
- 功能助剂：少量添加即赋予特定性能的物质（如抗氧剂→塑料、阻燃剂→建材）
- 催化剂：促进反应但不进入产品的物质（如钯催化剂→加氢）
- 溶剂/介质：反应载体或加工介质（如DMF→聚氨酯合成）
- 工艺辅料：不进入产品但工艺必需的辅助材料（如氮气→保护气）
- 中间品：本环节产品作为下游的原料出售（如氯化苄→下游医药/农药）

来源属性标准：

- 常规生产：独立产线定向生产，供应稳定，可调节，价格相对独立。
- 联产：与另一产品同时生产，通常比例固定，供应受主产品制约，价格与主产品联动。
- 副产：主产品的附带产物，供应被动，不可独立调节，通常折价销售。
- 回收再生：废旧产品回收再加工，供应受回收量制约，价格通常低于原生产品。
- 进口依赖：国内产能不足，大量依赖进口，供应受国际市场、贸易政策、汇率和关税影响。

常见错误对照（必须避免）：

- "联产""副产""回收再生" → 这是来源属性，不是功能角色
- "电子级化学品" → 这是品质分级，不是功能角色
- 不要因为原文同时提到"该产品是某工艺的副产物，主要作为阻燃剂使用"就只提取"副产品"或只提取"功能助剂"中的一个——应同时提取来源属性=副产 和 功能角色=功能助剂 两个实体

实体类型：

实体类型优先从以下类型中选择，必要时可新增更精确类型：

原料、中间体、产品、联产品、副产品、生产工艺、化学反应、催化剂、生产设备、企业、采购商、供应商、生产基地、CAS号、化学式、危险性、应用领域、终端行业、别名、简称、英文名、品质分级、准入合规、功能角色、来源属性。

（说明：产能、产量、消费量、价格、利润、库存、供需指标等数值/口径类信息不作为独立实体提取，只在"事件内容"中连同日期、数值完整保留，详见下方"必须提取和绝对不能提取成实体的类型"表，避免与该表的禁止性规定相矛盾。）

实体抽取规则：

1. 每一行只填写一个实体。
2. 同一个事件有多个实体时，重复填写相同的切片和事件字段，只改变实体字段。
3. 同一个事件的所有行必须使用完全相同的“切片编号”。
4. 一个单元格中只能写一个实体名称，不能把多个实体合并到一个单元格。
5. 相同实体必须尽量使用一致的“实体类型 + 规范名称”。
6. “实体说明”必须说明该实体在当前事件中的角色或关系，例如：

    - "ABS树脂的简称"
    - "该化工品的英文名"
    - "ABS树脂的并列下游应用领域之一"
    - "连续本体法生产ABS的生产工艺"
    - "2025年中国ABS产能规模"
    - "截至某日期当周的库存指标"
    - "该氢氟酸产品的品质分级，对应半导体刻蚀场景"
    - "生产该产品所需的生产端准入资质"
    - "该原料在下游生产中的功能角色，为核心原料"
    - "该产品的来源属性，为生物柴油生产的副产物"

## CSV 输出要求：

1. 只输出标准 CSV，不要输出解释、总结、项目符号、Markdown 代码块或额外文字。
2. 所有字段都使用英文半角双引号包裹。
3. 字段内部出现双引号时写成两个双引号。
4. 字段内部不要换行，原文换行改为空格。
5. 关键词之间使用中文分号“；”分隔。
6. 不要生成事件 ID、实体 ID、UUID 或数据库主键。
7. “切片编号”只要求在当前文档内唯一，从 1 开始递增。

第一行必须严格使用以下表头，不能改名、删列或增加列：

"文档标题","切片编号","切片标题","原文切片","事件标题","事件摘要","事件内容","事件分类","关键词","实体类型","实体名称","实体说明"

字段说明：

* 文档标题：原文标题；如果原文无标题，根据内容总结一个全局唯一标题。所有切片必须归属于同一文档。
* 切片编号：从 1 开始递增；同一事件的多行使用同一编号。
* 切片标题：简短、具体概括该切片事实。
* 原文切片：来自原文、可核验事实的完整内容。
* 事件标题：用“主体 + 动作 + 对象”概括事件。
* 事件摘要：一两句话概括事件。
* 事件内容：忠实重述事件完整事实，不能省略。
* 事件分类：例如产品定义、名称别名、生产工艺、产能建设、价格变化、利润变化、企业装置、供需变化、库存变化、应用领域、终端行业、指标变化、产业链关系。
* 关键词：使用“；”分隔。
* 实体类型：从推荐类型中选择。
* 实体名称：规范化实体名称。
* 实体说明：说明实体在当前事件中的角色和关系。

原文：“ABS树脂一般指丙烯腈-丁二烯-苯乙烯共聚物(Acrylonitrile butadiene Styrene copolymers)，简称ABS。”

- 产品：丙烯腈-丁二烯-苯乙烯共聚物
- 英文名：Acrylonitrile butadiene Styrene copolymers
- 简称：ABS

不要拆成多个名称事件。

原文：“ABS下游应用领域中，主要用于电子电器、交通工具、轻工业、办公设备、建材等领域。”

应生成一个事件：

事件标题：ABS应用于多个下游领域

该事件中抽取多个实体：

* 产品：ABS
* 应用领域：电子电器
* 应用领域：交通工具
* 应用领域：轻工业
* 应用领域：办公设备
* 应用领域：建材

不要机械拆成 5 个事件，除非原文分别给出每个领域的独立比例、变化、原因或结论。

原文：“电子电器领域的消费占比提升了1个百分点至64%，交通用具的消费占比保持在9%左右，建材及其他领域的需求占比从7%下滑至6%。”

1. 电子电器领域 ABS 消费占比提升 1 个百分点至 64%。
2. 交通用具 ABS 消费占比保持在 9% 左右。

1. 事件标题：电子级氢氟酸生产需安全生产许可证 实体：产品：氢氟酸；品质分级：电子级；准入合规-生产端准入：安全生产许可证
2. 事件标题：晶圆厂使用电子级氢氟酸需危化品使用许可证 实体：产品：氢氟酸；应用领域：晶圆制造；准入合规-使用端准入：危化品使用许可证
```

## 使用方法

1. 在网页版 AI 中上传文档并发送上述提示词。
2. 复制 AI 返回的整段 CSV，包括或不包括 ` ```csv ` 代码块均可。
3. 在 SAG 中选择项目，进入“文档”。
4. 点击“导入 AI 表格”。
5. 保持格式为 CSV，粘贴内容。
6. 点击“导入项目”。

## 导出备份重新入库

SAG 自身导出的 `*-knowledge-export.csv` 或 `*-knowledge-export.json` 也可以通过同一个“导入 AI 表格”入口恢复：

1. 新建或选择目标项目。
2. 进入“知识资产”，点击“导入 AI 表格”。
3. 选择导出的 CSV / JSON 文件。
4. 格式选择 CSV / JSON，或使用自动识别。
5. 点击“导入项目”。

导出文件中的多个文档会分别恢复。`system_event_id`、`system_chunk_id`、`system_entity_id` 只用于追踪，恢复时数据库会生成新的 UUID。结构化导入文件上限为 50 MB。
